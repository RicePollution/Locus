# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Locus is a SwiftUI iOS app that spoofs the device's GPS by injecting coordinates into `locationd`
through Apple's DVT location-simulation service — the same mechanism Xcode uses. It reaches that
service over an on-device developer tunnel using a vendored Rust FFI (`Vendor/idevice`, from
[jkcoxson/idevice](https://github.com/jkcoxson/idevice)). See `README.md` / `SETUP.md` for the
end-user story; this file covers how the code is put together.

## Fork

This repo is `RicePollution/Locus`, an independently maintained fork of `ChrisMack32/Locus` (MIT).
Remotes are wired so that:

```bash
git push origin main          # your fork
git fetch upstream && git log --oneline main..upstream/main   # what the original has added
```

`origin` → `git@github.com:RicePollution/Locus.git`, `upstream` → `https://github.com/ChrisMack32/Locus.git`.
The fork diverges from upstream **only** in identity and docs, which keeps future merges cheap — resist
reformatting or restructuring upstream code without a reason, since every such change is a future conflict.

The app deliberately ships under its own namespace so it installs *alongside* upstream's build rather
than fighting it. These five identifiers must stay in sync, and all of them cross an app boundary:

| Where | Value |
| --- | --- |
| `project.yml` → `PRODUCT_BUNDLE_IDENTIFIER` (and `bundleIdPrefix`) | `com.ricepollution.locus` |
| `Info.plist` → `CFBundleURLName` | `com.ricepollution.locus` |
| `Info.plist` → `UTTypeIdentifier`, and `PairingStore.supportedTypes` | `com.ricepollution.locus.rppairing` |
| `Info.plist` → `CFBundleURLSchemes` | `rplocus` |
| `LocalDevVPN.enableURL` → `?scheme=` | `rplocus` |

The last two are one contract: LocalDevVPN uses that query parameter to bounce back into this app after
connecting the tunnel, so changing one without the other silently breaks the return trip. Internal-only
strings (`locus.favorites` and friends in UserDefaults, the `LocusLocation` tunnel label, `Locus*` Swift
type prefixes) are sandboxed or cosmetic and are intentionally left alone to minimise the upstream diff.

`LICENSE` retains upstream's copyright line as MIT requires; the fork's line is additive. Do not remove it.

## Build

The project file is **generated by XcodeGen from `project.yml`** — but `Locus.xcodeproj/project.pbxproj`
is also committed. Sources are globbed from the `Locus/` directory, so **re-run `xcodegen generate`
and commit the result whenever a file is added, removed, or renamed**; editing target settings means
editing `project.yml`, never the pbxproj.

```bash
xcodegen generate
xcodebuild -project Locus.xcodeproj -scheme Locus -configuration Release \
  -destination 'generic/platform=iOS' DEVELOPMENT_TEAM=YOUR_TEAM_ID build
```

- `xcodebuild` needs full Xcode selected: `sudo xcode-select -s /Applications/Xcode.app`. On this
  machine `xcode-select -p` currently points at `/Library/Developer/CommandLineTools`, where
  `xcodebuild` refuses to run.
- **Simulator builds do not link.** `Vendor/idevice/libidevice_ffi.a` is a single arm64 slice built
  for `PLATFORM_IOS` (device), and `OTHER_LDFLAGS` links `-lidevice_ffi` unconditionally. Use a real
  device or `generic/platform=iOS`.
- `DEVELOPMENT_TEAM` is intentionally empty in `project.yml`; pass it on the command line or set it
  in Xcode's Signing tab rather than committing a team ID.
- There is no test target, no linter config, and no package manager. Verification is building and
  running on a paired device.

## Architecture

Three source groups under `Locus/`: `Engine/` (device plumbing, no SwiftUI), `Features/` (SwiftUI
screens), `Support/` (shared models and styling).

### The teleport path

`SpoofSession` → `LocationEngine` → C FFI → developer tunnel → `locationd`.

- **`LocationEngine`** (`Engine/LocationEngine.swift`) is the only code that touches the FFI for
  spoofing. It is an `enum` namespace holding four static `OpaquePointer` handles (adapter,
  handshake, remote server, location simulation), serialized by a private `DispatchQueue` with
  `.sync`. `set(...)` first tries `location_simulation_set` on the live handle; on any failure it
  tears everything down and rebuilds the whole tunnel from the pairing file. Two details that bite:
  the tunnel port `49152` is hardcoded, and `location_simulation_new` takes ownership of the remote
  server, so `remoteServer` is deliberately set to `nil` afterwards to avoid a double free.
  FFI integer codes are mapped to messages in `LocationEngineError.from(code:)` — those constants
  mirror the Rust side and must stay in sync with the private `Int32` constants above them.
- **`SpoofSession`** (`Engine/SpoofSession.swift`) is the `@MainActor` `ObservableObject` that every
  view observes — the single source of truth for status, pin, simulated coordinate, favorites, and
  recents. It owns three repeating timers, all of which exist for a reason:
  - **resend every 8s** — iOS drops the simulated fix if nothing re-asserts it;
  - **health check every 12s** — re-applies the last coordinate when `LocationEngine.isSessionActive`
    goes false or status is `.dropped`, which is what makes a session survive Wi‑Fi → cellular;
  - **joystick tick at 0.25s** — converts the pad vector into a metric offset at `TravelMode.baseSpeed`
    with ±10% jitter.

  Route following is a cancellable `Task` that interpolates between sampled coordinates and sleeps
  by distance/speed. Every coordinate change funnels through the private `apply(_:pairing:markRecent:)`,
  which is also where background-task and notification side effects live.
- **`TunnelConfig`** (`Engine/DeviceTunnel.swift`) resolves the tunnel IP (default `10.7.0.1`).
  **`LocalDevVPN`** (`Support/LocalDevVPN.swift`) detects the external LocalDevVPN app by URL scheme
  and infers "connected" by scanning `getifaddrs` for an address on the tunnel's /24.

### The two pairing paths

`PairingStore` owns one file: `Application Support/Pairing/rp_pairing_file.plist`, chmod `0600`.
`hasPairingFile` gates every spoof action.

- **iOS 18–26** — user imports an RPPairing plist. Three import routes exist deliberately because
  file pickers break under LiveContainer: the document picker
  (`Support/PairingDocumentPicker.swift`), `onOpenURL` in `LocusApp`, and
  `importPairingFromClipboard()`. `PairingStore.supportedTypes` is intentionally permissive (down to
  `.item`) because sideloaded plists often carry no usable UTI.
- **iOS 27+** — `PairOnDeviceService` runs idevice's blocking `pairable_host_accept` on its own
  `Thread`. C callbacks reach the main actor through free-function trampolines plus a
  `PairCallbackBox` holding a weak owner. `PairableHostAdvertiser` publishes the
  `_remotepairing-pairable-host._tcp` Bonjour service with an `NWListener` and **relays inbound TCP
  to the Rust listener on `127.0.0.1`** — the Rust `accept()` has to complete while iOS Settings is
  in the foreground, which is also why `SilentAudioKeepAlive` (looped near-silent WAV under the
  `audio` background mode) and a `CLLocationManager` keep-alive run for the duration.

### App shell and state

`LocusApp` picks `SetupFlowView` vs `RootView` from `SetupGate` (UserDefaults flags, defined at the
bottom of `Features/Setup/SetupFlowView.swift`), injects `SpoofSession` and `PairingStore` as
environment objects, and forces `.preferredColorScheme(.dark)`. `onOpenURL` routes pairing
extensions to `PairingStore` and `.gpx` to a `.locusImportGPX` NotificationCenter post.

All persistence is UserDefaults, no database: `locus.favorites` / `locus.recents` (JSON-encoded
`SavedPlace`, whose `id` is its `"lat,lon"` string), `locus.targetDeviceIP`, `locus.setupComplete`,
`locus.setupInProgress`.

## Conventions and constraints

- **`Locus/Resources/Info.plist` is hand-maintained** (`GENERATE_INFOPLIST_FILE: false`, and it is
  excluded from the sources glob in `project.yml`). Background modes, URL schemes, document types,
  and usage strings are edited there. Any new Bonjour service type must be added to
  `NSBonjourServices` or `NWListener`/browsing fails silently.
- Deployment target is **iOS 18.0**; anything newer is `#available`-gated — iOS 26 Liquid Glass in
  `Support/Theme.swift` (use the `locusGlass(...)` modifier rather than materials directly), iOS 27
  on-device pairing in `SetupFlowView` / `PairOnDeviceView`.
- `get-task-allow` in `Locus.entitlements` is intentional — the app is sideloaded with development
  signing.
- Errors surface to the user as `session.lastError` (an alert bound in `RootView` and
  `SetupFlowView`) and, for dropped sessions, a local notification. Prefer that over silent failure
  in Engine code; FFI errors must always be freed with `idevice_error_free`.
- The README's Pokémon GO section is a deliberate scope boundary: Locus is a system-level location
  override and explicitly does not patch or bypass any app's own location checks.
